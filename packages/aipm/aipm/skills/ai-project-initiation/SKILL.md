# AI 产品立项报告

## AIPM 调度契约

- **目标产物**：`project-initiation-report`。完整交付包括 Markdown 定稿和 HTML 单页；用户只要求某张立项卡片时，以该卡片为本次目标产物。
- **可接受输入**：一句话产品想法，或任何已有的产品、用户、业务、市场与方案材料。没有强制前置文档，因此 `dependencies` 为空。
- **两种调用方式**：用户直接要求立项产物时作为目标 skill；PRD 等下游任务缺少可靠立项依据时，也可由 AIPM 作为前置 skill 调用。
- **完成边界**：产出并确认本次目标后，把结果交还给 AIPM 调度器并停止。即使作为前置 skill，也不自行加载或执行 PRD、原型、测试等后续 skill。
- **确认点**：每站卡片和最终 Markdown 定稿都需要用户确认；红旗命中时必须暂停，不能把未确认判断继续传给下游 skill。
- **恢复位置**：从 `01-立项/00-盘点.md` 读取进度，复用已经确认的卡片，不重复询问已有信息。

两句话贯穿全程：

- **需求 ＝ 一个用户没被解决的问题**（做给谁，做什么）
- **立项 ＝ 拿证据换资源**（做不做，先做什么，投多少，什么时候停）

报告的读者是两类人：拍板的老板/管理层，和要一起干活的跨团队（研发、算法、业务方）。前者要一页看懂结论，后者要看懂范围、分工和不做什么。

## 硬规则

1. **分站推进，逐站确认**。每站产出一张卡，写入文件并展示给用户，用户明确确认后才进下一站。不得一口气跑完。
2. **发现问题就停**。命中任何「红旗」时，指出问题、说明依据、给出修改建议，然后等用户确认（采纳建议 / 坚持原判并记入风险）后才继续。不悄悄绕过，不替用户拍板。
3. **绝不编造**。数字、用户原话、竞品信息都要标证据等级和来源（见 [writing-rules.md](writing-rules.md)）。缺的东西写进「数据缺口」或「待验证假设」，不用估算填空。
4. **提问要省用户力气**。一次最多问 3–5 个问题，能做成选择题的用 ask_user_question，给出推荐项；先读用户已给的材料，材料里有的不再问。
5. **竞品与市场信息可以主动联网搜**，每条标出处和获取日期；搜到的结论以「待确认」呈现，由用户确认后才写进卡片。
6. **产物落盘**。所有中间产物和报告存到项目的 `01-立项/` 目录，可中断后接着做。重新进入时先读 `01-立项/00-盘点.md` 恢复进度。
7. **同步看板**。每站确认后调用 `aipm_stage`（action "update"，stage "01-立项"，status "in_progress"），在 note 里写明进度，例如"已完成第 3/8 站：需求池"。
8. **按需取用**。用户只要其中某一项产出时（例如只要竞品分析、只要 MVP 范围），只做对应的那一站，所需前置信息从项目里已有的材料读取，缺的简要询问，不要求补走前面的站。用户要修改已有卡片或报告时，直接在原文件上改。

## 流程总览

```
第 0 步 开场盘点 → 01 问题说清 → 02 找真用户 → 03 收进需求池
→ 04 看清对手 → 05 排出先后 → 06 拍板立项 → 第 7 步 写成报告
```

| 站 | 回答什么问题 | 产物文件 |
|---|---|---|
| 00 盘点 | 什么类型、给谁看、多久要、手上有什么 | `00-盘点.md` |
| 01 问题说清 | 到底是个什么问题？该不该用 AI？ | `01-问题定义卡.md` |
| 02 找真用户 | 谁真有这个问题，有多疼，证据呢？ | `02-用户与调研.md` |
| 03 需求池 | 到底有多少事要做？ | `03-需求池.md` |
| 04 看清对手 | 别人做了吗？凭什么是我们？ | `04-竞品分析.md` |
| 05 排出先后 | 先做哪个？第一版做多小？ | `05-MVP范围.md` |
| 06 拍板立项 | 值不值得投人投钱？AI 四问过不过？ | `06-决策矩阵.md` |
| 07 写报告 | 把前六站收成一份能拍板的文档 | `立项报告.md` → `立项报告.html` |

每站的方法、必问问题、卡片模板、过关标准和三类立项的差异，见 [stations.md](stations.md)。进入某站前先读该站内容。

## 第 0 步：开场盘点

先读用户给的所有材料，再用一轮提问补齐以下信息：

1. **立项类型**（决定后续打法）
   - `0→1`：新 AI 产品 / 新业务
   - `1→N`：已有产品的 AI 能力迭代、季度或半年规划
   - `B 端内部`：用 AI 替代或辅助企业内部的人工环节
2. **读者与场合**：给谁拍板、要对齐哪些团队、是会议汇报还是文档评审
3. **时间**：什么时候要交 → 决定走标准模式还是快速模式
4. **已有材料**：逐站盘点

把盘点结果写成 `00-盘点.md`：

```markdown
# 00 盘点 · <项目名>
- 立项类型：
- 读者：拍板人 / 对齐团队
- 截止时间：        模式：标准 / 快速
- 一句话原始诉求（原话照抄）：

| 站 | 状态 | 已有材料 | 缺什么 |
|---|---|---|---|
| 01 问题说清 | 已有 / 有但不达标 / 缺 | | |
| ...（02–06 同） | | | |

## 进度
- [ ] 01 … - [ ] 06   - [ ] 报告 MD   - [ ] 报告 HTML
```

「有但不达标」的站点照样要过关卡，只是从已有材料改起，不从零开始。

## 第 1–6 站：每站的固定动作

1. 读 [stations.md](stations.md) 中该站内容；涉及 AI 判断时同时读 [ai-checks.md](ai-checks.md)。
2. 从已有材料提取能用的部分，列出缺口，向用户提问补齐。
3. 按模板填出卡片，写入对应文件。
4. 对照该站「过关标准」逐条自查，在卡片末尾附「过关自查」清单，未过的项标红并给建议。
5. 展示卡片，等待用户确认。确认后更新 `00-盘点.md` 进度，并按硬规则第 7 条同步看板。

## 红旗：命中就停下来指出

| 红旗 | 出现在 | 怎么指出 |
|---|---|---|
| 问题定义里出现功能名（"做个 AI xx"） | 01 | 这是方案不是问题，反问"有了它想解决什么"，帮用户改写 |
| AI 适配三条件没有同时满足 | 01 / 06 | 说明缺哪条，追问"改流程能不能更便宜"，建议不用 AI 或缩小到满足条件的环节 |
| 只有"用户说"，没有"用户做过什么" | 02 | 说的不算，做过的才算；给出补访的好问题 |
| 结论没有原话或数字支撑 | 02 / 04 | 标为假设，列入待验证 |
| 需求说不清为什么重要 | 03 | 不进池 |
| 全是 P0 | 05 | 全是 P0 等于没有优先级；用"这一版不做，假设还成不成立"逐条过 |
| MVP 要验证的假设超过一个，或砍掉的没写理由 | 05 | 收窄到一个假设；补理由 |
| 业务方测算的收益当结果写 / 相关当因果写 | 06 | 改标"测算"，写清来源口径和试点里怎么验证 |
| AI 有最终决定权但没有兜底 | 06 | 明确 AI / 规则 / 人各管哪一段，建议影子模式起步 |
| 没有停止条件 | 06 | 补上"什么情况下停"和每阶段的闸门 |

## 第 7 步：写成立项报告

1. 读 [report-template.md](report-template.md)，按骨架把前六站的卡片收成 `立项报告.md`。
2. 按 [writing-rules.md](writing-rules.md) 自查：结论先行、证据有标、无黑话、没有功能名的问题定义。
3. 交给用户确认 Markdown 定稿。改到用户满意为止。
4. 复制 [assets/report.html](assets/report.html) 为 `01-立项/立项报告.html`，把定稿内容填进对应组件，删掉没用到的组件。用 `present` 交付 `立项报告.md` 和 `立项报告.html`，请用户打开检查版式。

报告写完不等于结束：把报告里的「决策待办」和「数据缺口」单独列给用户，提醒谁、什么时候要去补。

报告定稿后调用 `aipm_stage`（action "update"，stage "01-立项"，status "done"），在 note 里写明本次生成的文件。到这里任务结束，不自动进入其他阶段；可以在结尾建议用户下一步可能要做的工作，例如起草 PRD。

## 快速模式（时间紧，例如"周五就要方案"）

压成四道关卡，每道仍需用户确认：

1. **问题定义 + AI 三条件**（01 站精简版）
2. **证据盘点**：现有证据逐条分级，不足的直接列为待验证（02 站精简版）
3. **MVP 范围**：一个假设、必须做、明确不做、通过标准（03–05 站合并）
4. **决策矩阵 + AI 四问**（06 站）

快速模式只能产出「条件立项」版报告：结论写明"批准到第一个闸门为止"，所有跳过的站点和缺口进入「决策待办」，带责任人和时间。

## 边界：这个 skill 不做的事

- 不写 PRD，也不自动进入其他阶段。立项通过后需要 PRD 时，由用户另行提出。
- 不编造数据、用户原话、竞品信息；不用 AI 模拟访谈冒充真实样本。
- 不替用户拍板。skill 给建议和依据，结论由用户定。
- 不替研发估工时。需要工时的地方标"待研发估算"。
- 不给没有依据的收益预测。没有历史数据支撑的结果指标只定方向，不给具体数字。
