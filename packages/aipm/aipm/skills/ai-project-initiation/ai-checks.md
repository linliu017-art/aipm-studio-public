# AI 专项检查

AI 立项和普通立项一样要过三问（用户买不买、公司赚不赚、开发难不难），不一样的是还要多问四句，并且 AI 的错是概率性的，所以必须提前写好门槛、兜底和分阶段闸门。

---

## 一、该不该用 AI：三条件 + 两追问

三个条件**同时满足**才用 AI：

| 条件 | 判断方式 | 不满足时的信号 |
|---|---|---|
| 重复性高 | 每个人都在做同样的事，频次高 | 每次情况都不一样、低频 |
| 标准化程度高 | 好坏说得清：有明确的评判标准，且不同的人按标准判断结果一致 | 标准没写全；两个人对同一样本判断不同或理由不同；规则前后矛盾 |
| 人力瓶颈明显 | 人不够、太贵、要排队；规模增长时人工投入同步增长 | 人手充足，只是流程设计不好 |

**"标准化程度高"最容易被高估**。业务方说"有明确标准"时，要拿同一批样本让两个以上的人分别评判，核对分数、扣分理由、评分颗粒度是否一致。人自己都没统一的标准，AI 学谁的？不一致时，第一阶段的任务就是先统一标准，而不是开发模型。

两个追问：

1. **改流程能不能更便宜？** 如果调排班、加模板、改 SOP 就能解决，直接说不用 AI。
2. **模型变强以后，我们更值钱，还是被吞掉？** 如果基础模型或大平台下一版就能原生覆盖这个能力，护城河在哪？（专有数据、工作流嵌入、合规与责任承担、垂直场景深度）

还要排除**AI 物理上拿不到输入**的场景（例如关键信息发生在线下、AI 听不到看不到），这类先不做。

## 二、AI 多问四句

### 1. 该不该用 AI

回答第一节的三条件和两追问，写明结论用在哪个环节、不用在哪个环节。

### 2. 做到多好才算行

- **门槛是多少**：每项 AI 能力写可测的指标和阈值（准确率、召回率、证据正确率、延迟 P90、人—AI 一致性等）。
- **跟人比怎么样**：基线用人的表现。人与人之间的一致性是 AI 的天花板参考。
- **怎么测**：离线评测集从哪来、多少条、谁标注、覆盖哪些边界样本和红线样本。
- **"随便丢给模型"和"认真处理过的可控输出"要能区分、能衡量**，否则功能没法验收。没有评价标尺之前，质量优化就是盲优化。

### 3. 出了错，谁兜

把链路拆开，写清 **AI / 规则 / 人** 各管哪一段：

| 情况 | 系统怎么做 | 谁负责 |
|---|---|---|
| 正常 | | |
| AI 没把握（低置信度、证据不足、规则冲突） | 不输出确定结论，标"待复核"，转人工 | |
| 临界结果 | 转人工 | |
| 触发红线（越权、敏感信息、安全） | 中止输出、告警、冻结记录 | |
| 用户申诉 | | |

原则：

- 涉及正式决定（认证、处罚、绩效、资金、医疗、法律）时，AI 默认只做辅助，不拥有最终决定权。
- 首期优先**影子模式**：AI 跟着跑、给建议，人做决定，同时积累人—AI 一致性数据。
- 未经人工复核的 AI 结果不回写正式系统。

### 4. 数据和成本

- **数据从哪来，谁负责**：训练、评测、运行时数据各自的来源、Owner、权限；是否涉及个人信息、录音录像、客户数据，合规是否已批。没批的列为前置门禁。
- **用一次花多少**：单次调用成本（模型、语音、存储），乘以预期用量得到月成本；与被替代的人工成本对比。金额不确定时写"待报价后冻结"，按阶段审批。

## 三、POC、原型、MVP 的区别

| | 验证什么 | 给谁看 | AI 项目里的样子 |
|---|---|---|---|
| POC | 技术做不做得到 | 内部 | 拿一批真实数据离线跑，看指标到没到门槛 |
| 原型 | 用户看不看得懂、想不想要 | 目标用户 | 几张图或可点击 demo |
| MVP | 用户会不会一直用 | 真实用户 | 小范围真实使用，有通过标准 |

AI 项目通常先跑 POC。能先做异步、离线、低风险形态的，就别一上来做实时、在线、高风险形态；前者过闸后再进后者。

## 四、分阶段批钱的典型闸门

| 阶段 | 先验证什么 | 不过闸怎么办 |
|---|---|---|
| A 基线与标准 | 问题基线可量化；人工标准统一；数据权限到位；评测集建好 | 标准不统一就停止 AI 开发，先做标准 |
| B 离线评测 | AI 核心能力达到门槛 | 保留人工方案或重做标准，不进入下一阶段 |
| C 小范围上线 | 真实环境下的体验、稳定性、延迟、安全 | 降级为更简单的形态，不拖延整个项目 |
| D 试点决策 | 真实用户是否使用；是否节省人工；是否安全 | Go / Continue / Pivot / Stop，留下决策记录 |

阶段数和时长按项目调整，但每个阶段都必须写"不过闸怎么办"。

## 五、AI 项目的指标口径

- **过程指标**（AI 能力本身）：准确率、一致性、证据正确率、红线召回、延迟。
- **体验与使用指标**：完成率、使用频次、等待时间、满意度。
- **结果指标**（业务）：收入、转化、留存、人工工时。

首期通常以过程指标和使用指标作硬验收；结果指标受混杂因素影响大，没有对照实验时只观察、不作硬验收。
