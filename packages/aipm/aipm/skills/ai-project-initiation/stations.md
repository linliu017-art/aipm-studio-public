# 六站方法

每站结构：目的 → 步骤 → 必问问题 → 卡片模板 → 过关标准 → 三类立项差异 → 常见坑。

---

## 01 把问题说清

**目的**：把一句话诉求还原成一个具体的、没被解决的问题，并判断该不该用 AI。

### 步骤

1. **还原场景**，问齐五样才轮到功能：
   - 谁（具体到一类人，不是人口统计标签）
   - 何时何地（几点、在哪、跟谁）
   - 在做什么（手上正忙什么）
   - 卡在哪（哪一步过不去）
   - 现在怎么凑合（没有你，他怎么办）
2. **分开问题和方案**：听到功能名（"做个 xx""我们也上个 AI"）就反问"有了它，你想解决什么？"，改写成"谁 · 什么场景 · 卡在哪"。
3. **问三次为什么**：每次只追一层；用"他做过什么"校对"他说了什么"；停在自己能动手改的那一层，再往下就超出能改的范围。
4. **该不该用 AI**：读 [ai-checks.md](ai-checks.md) 第一节，三条件逐条判断。

### 必问问题

- 这个诉求最早是谁提的？原话是什么？
- 提出人真正担心的结果是什么？（追到代价：钱、时间、人、风险）
- 不做的话，现在大家是怎么凑合的？凑合的代价是什么？
- 为什么是现在？（窗口期、外部变化、内部瓶颈）


### 过关标准

- 一句话问题定义里没有功能名。
- "现在怎么凑合"和"代价"都写出来了。
- AI 三条件同时满足才写"用 AI"；不满足时结论要么改成不用 AI，要么缩小到满足条件的环节。

### 三类立项差异

- **0→1**：重点在场景还原和"为什么是现在"。
- **1→N**：先画产品**漏斗**（从可触达用户到深度用户的每一层人数和流失率），找流失最大或最被低估的那一段，问题定义落在那一段上。一份规划可以有 2–4 个问题，每个问题对应漏斗的一段，后面各自成为一个专题。
- **B 端内部**：业务方给的往往是方案（"用 AI 替掉 xx 岗位"），要改写成"人工投入随规模同步增长、哪个环节成为瓶颈"这类问题。写明当前流程中每个人工环节是谁做、花多少时间、做什么判断。

### 常见坑

- 把"用户想要 xx 功能"当问题。
- 场景写成"日常使用中"这类无法观察的描述。
- 问为什么问到"人性""行业现状"这种改不动的层级。

## 02 找到真用户

**目的**：确认谁真有这个问题、有多疼，用真实证据替换想象。

### 步骤

1. **分群**（选一种最贴合的分法）
   - 生命周期：新 / 活跃 / 沉睡 / 流失（沉睡和流失要带时间口径，如 90 天）
   - 消费能力：频次 × 金额四象限
   - 购买或使用动机：为什么来
2. **写画像**，写四样，不写人口统计：
   - 他知道什么
   - 他在乎什么
   - 他在什么时候用
   - 他因为什么卡住
   每个画像附一句原话、一件做过的事。
3. **去验证**，用研五步：
   1. 定目标：这次要弄清哪件事
   2. 选用户：重度（用到了哪个边界）、边缘（没想到的场景）、流失（为什么走、走去哪）、潜在（为什么还没来、卡在哪）
   3. 设计问题：问做过的事，不问看法；不带着答案去问（Mom Test）
   4. 执行：定量看多少（问卷、数据），定性问为什么（访谈、观察）
   5. 整理输出：每条结论配原话或数字

### 好问题 vs 坏问题（抽象模式）

| 坏问题 · 问看法 | 好问题 · 问做过的事 |
|---|---|
| 你觉得 AI 能帮你提效吗？ | 你目前最耗时间的一件工作是什么？上次是怎么做的？ |
| 用 AI 做 xx 是不是比手工好？ | 你做 xx 的流程是什么？哪一步最烦？ |
| 你喜欢这个功能吗？ | 你上次用它是什么时候？当时发生了什么？ |
| 如果有 xx，你会付费吗？ | 为了解决这个问题，你花过钱或时间吗？花在哪了？ |

### 过关标准

- 至少两个真实用户的原话。没有的话，本站只能产出调研提纲，并把需求方向标为"待验证"。
- 说和做矛盾时，信做的，并且要找到为什么不一样。

### 三类立项差异

- **0→1**：重点访潜在用户和替代方案的使用者（他们现在怎么凑合）。
- **1→N**：先用已有数据（漏斗、留存、VOC、差评、竞品实测）定位，再用少量访谈解释为什么。竞品对比实测（同一批被试、同一批任务、多维打分）是很强的证据。
- **B 端内部**：按**四种关系**拆角色，每种都要访到：
  - 实际使用者（谁在用）
  - 供给方（现在由谁人工提供这项服务，规模上来先被谁卡住）
  - 认证与复核方（谁打分、谁审核、谁对结果负责）
  - 结果影响方（管理者、下游、外部客户关心什么）
  另外要核查**"标准化程度高"是否属实**：同一样本让两个人分别评判，看结论和理由是否一致；评分规则是否写全、是否前后一致。人自己都没统一的标准，AI 学不了。

### 常见坑

- 画像写成"25–35 岁一线城市白领"。
- 访谈问"你觉得好不好"，得到一堆客气话。
- 把业务方的判断当用户证据。

## 03 收进需求池

**目的**：把调研结论拆成可登记、可追溯的需求动作，先进池，不排序。

### 步骤

1. **拆动作**：用户 → 需求 → 场景 → 问题 → 推出动作。一个问题可以推出多个动作。
2. **按字段登记**（见模板）。
3. **跟着状态走**：调研 → 设计 → 开发 → 测试 → 上线 → 迭代 / 下线，一直维护。

### 卡片模板

```markdown
# 03 需求池

| 编号 | 能力项名称 | 痛点 → 目标（一句话） | 建设方向 | 需求来源 | 提出方 | 对应问题 | 证据 | 状态 |
|---|---|---|---|---|---|---|---|---|
| R01 | | xx 太烦 → 做到 yy | 增长/转化/留存/体验/提效 | 业务提需/产品自驱/数据分析/用户反馈 | | 问题 1 | | 调研 |

## 未进池的诉求
| 诉求 | 不进池的原因 |
|---|---|

## 过关自查
- [ ] 每条都能追到来源（谁提的、哪句原话或哪个数据）
- [ ] 每条都连回 01 站的某个问题
- [ ] 说不清重要性的没有进池
```

### 过关标准

能说清"为什么重要"才进池。进池默认要做，只是排先后，所以门槛要卡住。

### 三类立项差异

- **1→N**：通常已有需求池（表格或多维表）。先导入盘点，按 01 站的问题归类；归不进任何问题的，列入"未纳入本轮"并写原因（与哪项重叠、属于缺陷流程、待澄清、依赖未就绪等）。
- **B 端内部**：业务方常给一份很长的功能清单，照样拆回到问题，不直接继承它的优先级标注。

## 04 看清对手

**目的**：回答"别人做了吗？凭什么是我们？"，产出差异化方向。

### 五步

1. **定目的**（目的不同，看的东西不同）
   - 0→1 要不要做：看市场、格局、有没有空白
   - 1→N 先迭代哪个：看对手功能和用户差评
   - 对手出招要不要跟：看它为什么做、用户买不买账
   - 定价：看定价页和成本结构
2. **找竞品，四类都要有**
   - 直接竞品：做一样的事，抢一样的人
   - 间接竞品：同一个需求，换一种方式
   - 替代品：用户现在怎么凑合（搜索、人工、表格、外包）
   - 潜在竞品：有能力进来、还没进来（平台方、基础模型厂商、硬件厂商自带能力）
3. **定维度**：四层拆解加市场层
   - 市场层：蛋糕多大、什么阶段、谁在抢
   - 用户层：用户旅程、完整输出物
   - 技术层：流程、分工、Agent 设计
   - 模型层：用什么模型、为什么
   - 基础层：数据来源、成本
4. **收信息**：自己注册走完主流程（含付费）；看应用商店好评和差评；看社区吐槽和测评；看官网、定价页、财报；看融资和招聘；看第三方数据平台。**每个数据标来源。**
5. **下结论**：差异化公式 + 做不做。

### 让 AI 唱反调

查完资料后必须做一次：

> 给出最有说服力的论证，说明为什么这个领域的某个竞争对手会成功、而我们会失败。

把最有力的三条反方论点写进卡片，并逐条回应（能化解的写怎么化解，化解不了的进风险）。

### 三类立项差异

- **0→1**：重点是市场层和潜在竞品（大平台或基础模型能力提升后会不会直接覆盖）。
- **1→N**：重点是逐项能力差距表 + 竞品商业模式。资源远少于头部时，结论通常是"学它的做法，不比它的规模，只抢最值钱的那部分"。
- **B 端内部**：竞品往往是"继续用人工""采购外部 SaaS""外包"，对比维度换成成本、质量一致性、可控性、合规。

## 05 排出先后

**目的**：先做哪个？第一版做多小？

### 三步

1. **Kano 分类**
   - 基本型：必须做（没有就不满意，做多了也不加分）
   - 期望型：做差异（越多越满意）
   - 兴奋型：放一个（没有不扣分，有了惊喜）
   - 反向型：别做（做了反而扣分）
2. **四象限排序**：价值 × 成本
   - 价值高、成本低：先做
   - 价值高、成本高：排进规划
   - 价值低、成本低：顺手做
   - 价值低、成本高：不做
   先问一句："这一版不做它，要验证的假设还成不成立？"不影响就往后放。
3. **定第一版（MVP）**
   1. 写下**一个**要验证的假设
   2. 只留验证它必需的功能，每一版都要能用（滑板 → 自行车 → 摩托 → 汽车，不是轮子 → 底盘 → 车身）
   3. 定通过标准

### 卡片模板

```markdown

|---|---|
```

### 三类立项差异

- **1→N**：在 MVP 之上多一层**专题拆解**：每个 01 站的问题成为一个专题，专题下拆任务，任务下挂需求。每条需求标：
  - 承接团队（客户端 / 后台 / 算法 / 固件 / 产品）
  - 对瓶颈团队的负载（重 / 中 / 轻）
  - 带来什么（对应漏斗哪一段）
  然后写**取舍原则**（3–5 条，每条附"怎么判断"），以及**资源不足时按什么顺序砍**（L0 绝不砍 → L3 先砍，写清为什么这样排）。砍的原则之一：先砍占瓶颈团队的非关键项；不占瓶颈的项砍了也缓解不了压力。
- **B 端内部**：业务方清单往往远大于 MVP。明确不做里通常包括：AI 自动做正式决定（认证、淘汰、绩效）、合规未批的数据使用、一次覆盖所有业务线。

## 06 拍板立项

**目的**：值不值得投人、投钱？结论只能三选一：做 / 不做 / 有条件做。

### 三步

1. **过三问 + 决策矩阵**，每问 1–5 分，写打分理由：

| 三问 | 等同于 | 打分 | 理由与证据 |
|---|---|---|---|
| 用户买不买？ | 市场有蛋糕吗？ | 1–5 | |
| 公司赚不赚？ | 能赚到钱 / 知名度 / 省下成本吗？ | 1–5 | |
| 开发难不难？ | 我们能做吗？（技术、数据、合规、人力） | 1–5 | |
| **结论** | 做 / 不做 / 有条件做 | | |

2. **AI 多问四句**：读 [ai-checks.md](ai-checks.md) 第二节，逐条回答。
3. **定阶段与停止条件**：钱分阶段批，先批到第一个评测闸门为止；每阶段写"先验证什么、主要产出、不过闸怎么办"；最后一个阶段做 Go / Continue / Pivot / Stop 决策。

```markdown
|---|---|---|

**<做 / 不做 / 条件立项>**。批准 <范围、时长、模式>；首期只验证 <一个假设>；AI 不拥有 <哪些决定权>；<第几周> 依据 <什么数据> 做 Go / Continue / Pivot / Stop 决策。

- [ ] 写了停止条件
```

### 三类立项差异

- **0→1**：通常是条件立项：先 POC 再 MVP。
- **1→N**：用**外部锚点倒推版本节奏**（大促、新品上市、财年节点），写清每个版本窗口的锁版和全量时间，指出最紧的一版和原因。附**决策待办**（事项、内容、责任人、时间）。先列需求、再谈资源、最后取舍，顺序不能反。
- **B 端内部**：首期常用**影子模式**（AI 跟着跑，不做决定），先在一个小范围（一个班组、一条业务线）试点。
