# 公司调研 HTML 排版规范

本 reference 只服务 `company` 模式的单文件 HTML。Markdown 是唯一内容真源；HTML 负责阅读层级、导航、响应式与打印，不维护第二份正文，也不改变研究结论。

## 1. 阅读目标

报告应同时支持三种阅读路径：

1. **3 分钟速读**：从标题、元信息、公司总览和关键结论判断是否继续研究。
2. **按专题阅读**：业务报告与技术报告各自可独立读懂，不依赖来回跳章。
3. **证据回查**：正文来源 ID 可以快速跳到来源表，再返回原位置或打开原文。

飞书富文档只提供信息组织启发：结论先行、层级清楚、表格承载比较、风险单独突出。不要照搬飞书 XML、彩色 callout、emoji 或内部证据标签。

## 2. 页面结构

HTML 保持一份连续文档，主内容只映射 Markdown 的五个 H2：

1. 公司总览
2. 业务报告
3. 技术报告
4. 财务、商业质量与风险
5. 来源与信息缺口

推荐页面区域：

- `header`：企业简称、报告类型、主体、截止日、版本等必要元信息。
- `nav`：五模块目录；长文档可显示 H3，但默认不超过两级。
- `main`：完整报告正文。
- `footer`：仅放生成日期或必要的使用说明，不重复来源与结论。

公司总览优先呈现结论与少量关键指标；业务报告先呈现产品组合和经营链贯通矩阵；技术报告先呈现证据边界和产品—技术映射；财务模块先呈现可比数字，再解释商业质量与风险；最后集中放来源和信息缺口。

## 3. 视觉基线

整体调性是“白纸、墨字、克制、可信”。报告是专业阅读页面，不是营销落地页。

### 3.1 颜色

使用语义 token，组件不散落近似色：

```css
:root {
  --report-bg: #ffffff;
  --report-surface: #f8f8f8;
  --report-text: #171717;
  --report-text-strong: #191919;
  --report-text-secondary: #666666;
  --report-text-subtle: #767676;
  --report-border: #eeeeee;
  --report-divider: #f0f0f0;
  --report-border-strong: #d1d5db;
}
```

- 页面、侧栏和卡片以白底为主；浅灰只用于必要的分组和表头。
- 正文用柔黑，不用纯黑大面积压迫阅读。
- 业务小字不得浅于 `#767676`；`#767676` 只用于白底，在 `#f8f8f8` 浅灰面上改用 `#666666` 或更深。正文对比度至少达到 WCAG AA。
- 风险可用柔和红色作为辅助，但必须同时有“风险”等文字或结构标识，不能只靠颜色传义。
- 禁止渐变、彩色大底、霓虹、玻璃拟态和装饰性色带。

### 3.2 字体与字重

```css
--report-font: -apple-system, BlinkMacSystemFont, "PingFang SC",
  "Hiragino Sans GB", system-ui, "Segoe UI", "Microsoft YaHei", sans-serif;
```

- 不加载 webfont；正文、表格、按钮和导航主体统一使用系统字体。来源 ID、序号或代码可使用系统等宽字体，但不能让整段中文变成等宽体。
- 只用 `400 / 500 / 600` 三档字重；中文小标题以 `500` 为主，H1 和关键数字可用 `600`，禁用 `700+`。
- 建议字号：H1 `32px`，H2 `24px`，H3 `20px`，正文 `16px`，说明与导航 `14px`，日期/脚注 `12px`。
- 正文行高不低于 `1.65`；标题行高 `1.2–1.35`；正文不使用负字距。
- 中文与英文、数字、技术标识之间保留合理空格；日期统一 `YYYY-MM-DD`，大数字使用千分位。

### 3.3 边界与层级

- 默认卡片：白底、`1px solid var(--report-border)`、`8–12px` 圆角、`16–24px` 内边距。
- 卡片内部的分隔线用 `--report-divider`，外轮廓用 `--report-border`；交互 hover 才使用 `--report-border-strong`。
- 分隔线与正文左右对齐，不贯穿到带内边距容器的外缘。
- 禁止 `box-shadow`。层级只靠字号、字重、留白、浅灰底和边框建立。
- 禁止 emoji。状态、提示和控件使用文字；确需图标时使用单色 SVG，并提供可访问名称或设为纯装饰。

## 4. 信息组件

组件按内容需要使用，不设置数量指标，也不强制每章出现卡片。

### 4.1 摘要与关键结论

- 公司总览开头可以使用一个浅灰摘要区，呈现 3–5 条真正影响判断的结论。
- 结论使用完整句，不把“已核验 / 推断 / 待确认”等内部标签做成视觉徽章。
- 重要限制用自然语言紧邻相关结论，不在页面顶部堆免责声明。

### 4.2 指标

- 只把主体、报告期和口径明确的关键数字做成指标卡；注册资本、融资额、GMV、用户数不能因卡片化而暗示为收入。
- 每个指标同时显示单位和期间，必要时显示来源 ID。
- 指标组在桌面端最多 4 列；移动端单列或两列，不能挤压文字。

### 4.3 表格

- 表格只承载字段映射或横向比较；单个事实用段落。
- 经营链贯通矩阵按固定顺序展示：产品/服务、客户与付费方、交付方式、技术支撑、变现方式、来源。
- 表头使用浅灰底和 `500` 字重，单元格顶部对齐，长文本保持可换行。
- 宽表外包一层可横向滚动容器；页面本身不得出现横向滚动。
- 不能用缩小到不可读的字号换取“整表塞进一屏”。打印时允许表格跨页，并重复表头。

### 4.4 提示与风险块

- 适合突出“核心结论、关键限制、风险、下一步”的短内容；普通叙述不套框。
- 默认使用浅灰底或左侧柔黑边线。风险块可用低饱和红色边线与文字，但同时显示明确标题。
- 不用 emoji、渐变、阴影或大面积高饱和背景。

### 4.5 来源与链接

- 正文 `[S01]` 等来源 ID 是可聚焦链接，跳到来源表对应行；来源行应有稳定 `id`。
- 外部链接保留下划线或其他非颜色线索，打开方式不妨碍复制 URL。
- 链接文本说明来源名称，不用裸写“点击这里”。

## 5. 布局与交互

- 页面最大宽度建议 `1200px`；正文阅读列建议 `760–880px`，宽表可在主内容边界内扩展。
- 桌面端可使用 `220–260px` 目录 + 主阅读列；目录使用边框与留白区分，不用阴影。
- 间距采用 `8px` 基线：段落 `12–16px`，卡片内部 `16–24px`，同级块 `16–24px`，H2 模块之间 `40–56px`。
- 折叠只用于降低长报告滚动成本，不能通过懒加载让搜索或打印丢失正文。默认打开公司总览；其他模块的状态由用户明确操作控制。
- 折叠控件必须使用 `<button>` 或 `<details><summary>`，同步 `aria-expanded`，支持 Enter / Space，文字说明“展开/收起 + 模块名”。
- 动画仅限短暂的边框或展开过渡，不使用抬升、缩放和视差；支持 `prefers-reduced-motion`。

## 6. 响应式

至少覆盖 `390×844`、常见平板和 `1440×900`：

- `< 640px`：单列，页面左右 padding `16px`；侧栏目录隐藏或变成文档顶部的语义导航；H1 可降至 `28px`，H2 不低于 `22px`，正文保持 `16px`。
- `640–1024px`：单列或窄目录，内容优先；多栏指标降为两列。
- `≥ 1024px`：显示完整目录与主阅读列；`≥ 1280px` 时整体居中。
- 所有按钮和折叠控件触控区域至少 `44×44px`。
- 任何视口下都应满足 `document.documentElement.scrollWidth === document.documentElement.clientWidth`；宽表只在自身容器滚动。
- URL 锚点跳转应预留标题上方空间，避免标题被固定栏遮住。

## 7. 可访问性

- 使用 `header / nav / main / section / table / footer` 等语义元素；标题层级连续，不用样式伪装标题。
- 页面第一个可聚焦元素提供“跳到主内容”的 skip link。
- 所有交互用原生 `<button>` / `<a>`；不使用只有 `onclick` 的 `<div>`，不使用正数 `tabindex` 重排。
- 保留浏览器原生键盘焦点指示，不写 `outline: none`。如果自定义 focus，必须清楚且对比度足够。
- 正文文字对比度至少 `4.5:1`，大字至少 `3:1`；风险与状态不能只靠颜色区分。
- 目录当前项使用 `aria-current="location"`；图标按钮提供“动词 + 对象”的 `aria-label`。
- 表格使用 `<caption>` 或邻近标题，`th` 正确设置 `scope`；来源链接有可理解名称。
- `prefers-reduced-motion: reduce` 时取消平滑滚动和纯视觉动画。
- 五个模块的正文与来源在完成渲染后都存在于文档结构中；折叠只改变显示状态，不删除内容节点。

## 8. 打印

HTML 必须可以直接打印为干净的 A4 报告：

```css
@page { size: A4; margin: 16mm; }

@media print {
  nav, .toolbar, .theme-toggle, .collapse-control, .skip-link {
    display: none !important;
  }
  body, main { background: #fff !important; color: #171717 !important; }
  main { width: 100% !important; max-width: none !important; margin: 0 !important; }
  article, section, .card { box-shadow: none !important; }
  h1, h2, h3, table, figure { break-after: avoid-page; }
  tr, blockquote, .callout { break-inside: avoid; }
  thead { display: table-header-group; }
  a { color: inherit; text-decoration: underline; }
}
```

- 打印前展开全部折叠模块；如交互实现会记录折叠状态，用 `beforeprint` 临时展开、`afterprint` 恢复。
- 隐藏目录、主题切换、折叠按钮和仅屏幕可用的控件；正文、来源与信息缺口不能隐藏。
- 不依赖背景色表达关键信息；黑白打印仍能通过标题、边框与文字识别层级。
- 避免标题孤行、卡片被不必要切断和超宽表格裁切；必要时让宽表在打印样式中按列换行或转为纵向块。

## 9. 验收

静态审计之外，HTML 发生样式、布局、交互或打印规则变更时抽查：

- 桌面端与 `390×844`：五模块、目录、锚点、折叠和宽表可用，页面无横向溢出。
- 键盘：skip link、目录、来源链接和折叠控件顺序合理，焦点可见。
- 视觉：白底柔黑、系统字体、无渐变、无阴影、无 emoji；边框和留白形成层级。
- 控制台：正常联网时无脚本错误；全部模块已经渲染且折叠不会删除正文节点。另模拟 CDN 不可达，确认显示完整 Markdown 原文、打印可用且不执行原文中的 HTML；单独缺少图表库或图表语法错误时仍保留图源码。降级模式不能计为完整富排版验收通过。
- 打印预览：全部正文展开，导航与控件隐藏，来源保留，A4 无明显裁切。

通过这些检查只证明当前 HTML 的阅读与交付质量，不替代报告事实审计。
