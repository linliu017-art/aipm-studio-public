# 面试后情报回流 SOP · v1.0

> 2026-05-16 新增。面试调研工作流的"后置闭环"——把每场面试拿到的真实家底情报回流到作战地图 + 沉淀通用经验到 references，让下一场二面/三面/同类型公司复用。
>
> **核心洞察**：调研只能拿到 60-70% 公开情报，剩下 30-40% 必须靠面试现场"反问 + 听话听音"补完。如果不把这 30-40% 沉淀下来，每次面试都在原地重走调研路径。
>
> **触发条件**：用户在 interview-research 跑完作战地图后**真去面试了，并提供了复盘材料**（飞书 wiki / 录音转录 / 笔记）→ 自动跑本 SOP Step 8。

---

## Step 8 · 面试后情报回流（4 阶段）

### Stage 1 · 真实情报 vs 调研预判 Diff（10 分钟）

**输入**：作战地图 v1（调研产出）+ 面试复盘材料（用户提供）

**输出**：`面试作战地图_v2.md` 的 Diff 报告，按 5 类对照：

| 维度 | 调研预判 | 真实情况 | 误判等级 |
|---|---|---|---|
| 核心产品 | ... | ... | 🔴 P0 / 🟡 P1 / 🟢 P2 |
| 商业模式 | ... | ... | ... |
| 岗位真实定位 | ... | ... | ... |
| 面试官画像 | ... | ... | ... |
| 考察重心 | ... | ... | ... |

**误判等级判定**：
- 🔴 P0 = 直接导致面试翻车（如核心产品错、岗位类型错、面试官类型错）
- 🟡 P1 = 重要遗漏（如 B/C/G 三端结构、海外规划 timing、前身工具识别）
- 🟢 P2 = 次要不足（如反问追问深度、应对策略缺一类话术）

### Stage 2 · 作战地图升级（v1 → v2）

**🔴 文件命名铁律**：
- v1 调研基线产出 = `面试作战地图.md` + `.html`（**不动，不覆盖**，是历史基线）
- v2 回流升级版 = `面试作战地图_v2.md` + `.html`（新建，保留与 v1 对比能力）
- 如有 v3 / v4（二面后再回流）= `面试作战地图_v3.md` 以此类推
- **同目录共存**，便于看到调研→面试→再调研→再面试的演化路径

按 Diff 报告**新增章节/段落**到原作战地图，不删旧内容：

| 升级动作 | 落到作战地图的哪个章节 |
|---|---|
| 真实核心产品识别 | Ch4 已成型产品矩阵 → **新增段**"面试官 R-XX 提到的实际重点产品" |
| 真实商业模式（如 web3 alpha / token / 算力分账等）| Ch6 商业化 → **新增段**"创新经济模型现场情报" |
| 真实岗位定位 vs JD | Ch6 岗位解剖 → **新增段**"面试现场校准：实际工作内容" |
| 真实面试官类型 vs 预判 | Ch5 面试官画像 → **新增段**"面试官现场二次识别" |
| 现场拿到的金钩子情报 | Ch11 反问 & 注意事项 → **新增段**"已挖到的家底情报清单" |
| 翻车点 & 教训 | Ch11 红线 → **新增段**"本场翻车点 → 下场预案" |

**输出**：`面试作战地图_v2.md` + `面试作战地图_v2.html`，**保留 v1 不覆盖**，便于复盘对比。

### Stage 3 · references 通用化沉淀（核心价值）

把本场翻车点抽出来，按"是否通用"分类：

#### 🌐 通用沉淀（升级 skill 全局）

| 翻车点 | 升级位置 |
|---|---|
| 面试官类型预判错 | `references/archetypes-library.md` Part D 追加误判案例 + 反思识别算法 |
| PM 类型 JD vs 实际错配 | `references/archetypes-library.md` Part B.2 算法权重调整 |
| 反问没追金钩子 | `references/hejinhua-experience.md` C 节追加"金钩子追问公式" |
| 被否决继续辩护 | `references/hejinhua-experience.md` J 节"被否决 3 步话术" |
| 演示物没准备 / 续场策略缺失 | `references/hejinhua-experience.md` D 节扩"演示物 + 续场" |
| 新的公司类型套路（如 AI + 科研工具）| `references/hejinhua-experience.md` B 节新增类型 |

#### 🎯 单场特化沉淀（仅本公司用）

| 沉淀点 | 落到哪里 |
|---|---|
| 公司家底（产品 / 商业模式 / 团队）| 本公司作战地图 v2 |
| 本场面试官个人画像（爱好 / 风格 / 倾向）| 本公司作战地图 v2 Ch5 |
| 本公司特有的"被否决话术"实例 | 本公司作战地图 v2 Ch11 |

### Stage 4 · 下场预案（二面/终面准备清单）

如果用户还有下一场（二面 / 终面 / 同集团其他子公司）：

| 预案项 | 内容 |
|---|---|
| 必补功课清单 | Stage 1 标 🔴 的所有维度，24h-48h 内必补 |
| 反问升级清单 | 现场拿到金钩子情报的延伸追问（如 "海外版第一目标市场" 已知 → 下场反问 "第一年 ARR 目标 / 销售模式 / 本地化策略"）|
| 翻车点预案 | 上场翻车的题目（如 R03 抛方案被否决）→ 写好下场标准答案 |
| 自我介绍升级 | 把上场反馈正向信号挂回去（如面试官夸"想法活跃" → 下场开场用"我擅长在业务卡点上给跨职能方案"）|

**输出位置**：`{NN_公司名_岗位}/下场预案_{二面/终面}.md`（与作战地图同目录）

### Stage 5 · 仪表盘卡片状态升级（v3.2 新增）

回写 `00_工作流浏览页.html`（仪表盘）的本公司卡片，让浏览主页时**一眼看出面试进展**：

| 升级动作 | 改 HTML 的哪里 |
|---|---|
| ① 版本角标 | `meta-status` 状态行从 `✨ v1 · {章节摘要}` 升级为 `🎙️ v2 · 已面试 · {日期}` |
| ② 面试结果标记 | 状态行追加 `· 一面 ✅通过 / ⚠️待定 / ❌挂` |
| ③ 重大误判预警 | 如 Diff 报告 P0 ≥ 2 处 → 在 company-name 后加 ⚠️ emoji + tooltip `"调研有重大误判，看 v2"` |
| ④ 多版本指向 | `company-card` 的 `href` 改为指向 `面试作战地图_v2.html`（v1 仍可通过点开目录访问）|
| ⑤ tier 升降（可选）| 如二面被刷 → tier 改为 `已挂`（灰色）；如终面通过 → tier 改为 `已 offer`（金色）|

## 触发器（什么时候自动跑 Step 8）

用户消息中出现以下任一信号 → 主动建议跑 Step 8：

- **明确触发**：用户上传/粘贴面试复盘材料 + 提到本作战地图对应的公司
- **隐式触发**：
  - "面试结束了" / "面完了" / "面挂了" / "拿到 offer"
  - "面试官说 X / 现场发现 Y"（暗示有现场情报）
  - "下场二面/终面要准备什么" → 必须先跑 Stage 1-2 再准备
  - "这家公司还要继续投/换部门重投" → 先回流情报

**主动建议话术**：
> "你已经面完一场，作战地图 v1 是基于公开情报跑的，可能有错配。要不要先跑 Step 8（面试后情报回流）：① 真实 vs 预判 Diff ② 作战地图升级到 v2 ③ references 通用化沉淀。下场二面前必做这一步，否则等于在错误地图上准备。"

## 与其他 skill 的关系

| skill | 边界 |
|---|---|
| `interview-review` | 复盘**候选人表现**（话术好坏 / 翻车点）→ 本 Step 8 复盘的是**调研失误**（情报错配）。两者并行不重复 |
| `interview-knowledge-feedback` | 把面试**知识点**蒸馏成个人体系 → 本 Step 8 蒸馏的是**调研方法论**。两者输入相同（复盘材料）输出维度不同 |
| `interview-demo-builder` | 基于作战地图 v2（不是 v1）做演示 demo → Step 8 是 demo-builder 的前置依赖 |
| `autoskill` | 跨会话蒸馏偏好 → 本 Step 8 是 interview-research 专属的"垂直自我迭代"，autoskill 是水平的 |
