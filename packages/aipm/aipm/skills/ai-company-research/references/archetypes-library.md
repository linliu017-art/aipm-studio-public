# 面试官 + PM 类型对策库 · v1.0

> 2026-05-16 新增。源起于一次"沁言学术作战地图与真实面试错配"复盘——作战地图预判面试官是技术深究型 CEO，实际遇到的是国内业务线整体负责人（业务总操盘手 + 喂结论否决型），导致 100 道压题方向全错。
>
> 本 references 是 interview-research skill 的**通用类型库**：
> - **面试官 4 类型**：决定考察重心 + 应对范式
> - **PM 4 类型**：决定岗位真实定位 + 自我介绍主线 + 压题方向
>
> 适用于任何公司任何岗位。每次跑面试调研前必读，用于在 Ch5（面试官画像）+ Ch6（岗位解剖）+ Ch9（题库）中做"类型对齐"。

## Part A · 面试官 4 类型对策

### A.1 类型识别速查表

| 类型 | 典型职能 | 识别信号（JD/HR/邮件） | 说话风格预测 |
|---|---|---|---|
| 🧑‍💻 **技术深究型** | CTO / 算法负责人 / 技术 BOSS / 资深工程师 | JD 强调"架构 / 算法 / 模型 / RAG / Agent 工程" + 招聘流程含"技术面"+ HR 提到"会问技术问题" | 深问技术细节 + 喜欢白板题 + 介意名词混淆 + 追问失败 case 根因 |
| 👔 **业务总操盘手** | 业务线负责人 / 创始团队核心 / 国内/海外业务 BOSS / 直属带人的 leader | JD 强调"负责整体落地 / 协同各岗位 / 业绩负责" + 公司规模 50-300 人初创 + 招聘者是部门负责人 | **喂结论 + 直接否决** + 大段抛真实业务现状 + 暴露真实痛点 + 不留情面 |
| 🏢 **HR 流程型** | HR / 招聘专员 / 人力总监 / BP | JD 模糊 + 第一轮是 HR 面 + 邮件由 HR 直接发 + 已上市/中大型公司 | 软性 + 履历真实性 + 文化适配 + 薪资期望 + 离职原因 |
| 🎯 **CEO 战略型** | CEO / 创始人 / 联合创始人 | 终面环节 + 公司天使-A 轮 + JD 提"和创始人聊"+ 邮件由 CEO 直接发 | 远期愿景 + 行业判断 + 创始人理念 callback + 看 fit not skill |

### A.2 每类型的考察重心 + 应对范式

#### 🧑‍💻 技术深究型

- **考察重心**：技术深度 70% / 产品方法 20% / 软性 10%
- **典型问题**：模型选型对比 / Agent 框架细节 / RAG 高阶 / 抗注入设计 / 性能基准 / 5-Why 根因
- **应对范式**：
  - ✅ 100 题技术压题主战场
  - ✅ 必备白板演示能力（4 层架构 / 3 层模型选型 / 4 道门 RAG）
  - ✅ 失败 case 复盘 + 认知升级一定要讲
  - ❌ 不要堆工具（一连串 5+ 工具名 = 不专业）
  - ❌ 技术名词混淆是死罪（OpenClaw ≠ Codex / MCP ≠ Tool Calling ≠ A2A）

#### 👔 业务总操盘手（🔴 最难应对，但情报盘口最大）

- **考察重心**：真实摸家底 35% / 业务总线能力 30% / 学习+认错速度 20% / 履历真实性 15%
- **典型问题**：不按模板题，**直接抛业务现状/痛点让你接** → "你说怎么办" / "我们的核心痛点是 X，你有想法吗"
- **应对范式（生死攸关）**：
  - ✅ 对方抛痛点 → **先反问 3 件家底事，再决定要不要给方案**
  - ✅ 自己的方案被否决 → **立刻接受 + 主动暴露知识缺口 + 反问家底**（详见 hejinhua-experience.md J 节"被否决 3 步话术"）
  - ✅ 反问环节是主战场（不是 8 个标准反问，而是**每个反问后追 1-2 层金钩子**，把面试官当作"业务情报源"挖）
  - ✅ 大段听完对方业务现状 → 接 1 句话连接自己项目可迁移经验（"这跟我做 XX 时遇到的 YY 问题逻辑一样"）
  - ❌ **绝对禁止：没摸家底就抛方案** = 翻车 #1
  - ❌ **绝对禁止：被否决继续辩护** = 翻车 #2（用其他维度绕开核心反驳）
  - ❌ 不要堆方法论 / 教科书框架（业务总操盘手反感"AI PM 套话"）

#### 🏢 HR 流程型

- **考察重心**：履历真实性 40% / 软性匹配 30% / 文化适配 20% / 薪资预期 10%
- **典型问题**：自我介绍 / 离职原因 / 期望薪资 / 个人优劣势 / 团队冲突 / 文化适配
- **应对范式**：
  - ✅ STAR 万能答题（每题 Situation → Task → Action → Result）
  - ✅ 离职原因必须形成闭环（不是"环境变了"，是"下一步要找 XX 因此选择简圣"）
  - ✅ 薪资期望不报数字 → "按贵司 JD 范围 + 我的能力增量定，比较灵活"
  - ✅ 减少技术黑话，多用产品价值描述
  - ❌ 初面问钱 / 报销 / 调休 = 已知雷区
  - ❌ 简历留白（学校 / 毕业时间 / 项目时长）= 必被追问

#### 🎯 CEO 战略型

- **考察重心**：远期愿景对齐 30% / 行业判断 25% / fit 20% / 学习能力 15% / 项目质感 10%
- **典型问题**：你怎么看行业趋势 / 为什么加入我们 / 你 5 年想做什么 / 如何看 AGI/某新技术
- **应对范式**：
  - ✅ 主动 callback CEO 公开访谈原话（K姐/36氪/媒体专访）
  - ✅ 远期话术（3-5 年规划）+ 创始人理念契合点
  - ✅ 行业判断要有自己结论，但留余地（"我倾向 X 但要看 12 月窗口期 Y 因素"）
  - ✅ "加入动机"必须三个层次：业务 + 团队 + 成长
  - ❌ 不要堆战术细节（CEO 不关心，关心的是结构性判断）
  - ❌ 不要顺杆爬"你说什么我都同意" = 没有自己观点

### A.3 类型混合的实战识别

实战中面试官常有混合特征。识别公式：

```
真实类型 = 主类型（70%）+ 副类型（30%）

例 1：CEO + 技术深究 → 罗实型（清华工程师创业 CEO）→ 主 CEO 战略 + 30% 技术
例 2：业务线 leader + HR 流程 → 国内业务负责人（创始团队）→ 主业务总操盘手 + 30% 履历真实性
例 3：CTO + 业务总操盘手 → 初创公司 CTO 兼 BD → 主技术深究 + 30% 业务摸家底
```

**调研时强制识别动作**：在 Ch2 公司全景 / Ch6 岗位解剖里**明确写出预测主+副类型**，并对应配 100 题压题比例。

### A.4 类型预判误判后的纠错

⚠️ **重要**：调研阶段的类型预判**可能错**（公开信息有限）。**面试前 5 分钟内必须二次识别**：

| 时机 | 二次识别动作 |
|---|---|
| HR 电话约面试 | 问"对方是哪个职能/角色"→ 确认主类型 |
| 面试官加微信/钉钉 | 看头像 + 微信名 + 朋友圈倾向（技术 / 业务 / 高管）|
| 面试开场 1 分钟 | 听 ① 自我介绍是技术 vs 业务 ② 开场问题是"展开讲项目"（技术）vs"了解一下你"（HR）vs"我们公司怎么样"（业务 BOSS）|

**如果预判错位**，立刻心理切轨：
- 准备的 100 道技术题用不上 → 切换到"反问家底 + 业务总线话术"
- 准备的反问家底用不上 → 切换到 STAR 软性答题
- **不要硬刚自己准备的版本** = 第三种翻车

## Part B · PM 4 类型对策（决定自我介绍主线 + 压题方向）

### B.1 类型识别速查表（基于 JD 关键词扫描）

| PM 类型 | JD 关键词信号 | 真实工作内容 | 占比预测 |
|---|---|---|---|
| 🤖 **技术 AI PM** | "Agent 编排 / Skills 评测 / RAG 架构 / 模型选型 / Tool Calling / 多模态" + "输出高质量 PRD" + 加分项含"AI coding 工具" | Agent 工作流产品化 + 评测体系搭建 + 模型选型 + 技术方案 PRD | 业界 30% |
| 📊 **业务总线 PM** | "负责整体落地 / 协同各岗位 / 推广宣发 / 直播间 / 分公司协同 / B 端方案 / 配合市场" + "业绩 / 增长负责" | PM 管运营、市场、开发、宣发、直播间、B 端方案、分公司——业务 hands-on 全管 | 业界 25% |
| 📚 **内容运营 PM** | "数字人 / 矩阵号 / 私域 / 内容资产 / Prompt 工程师 / 智能体运营 / 知识付费" | 懂 AI 的内容运营 + Prompt 工程 + 数据驱动 + 矩阵号操盘四合一 | 业界 20% |
| 🏭 **行业方案 PM** | "ToB 解决方案 / 行业客户共研 / 客户成功 / 行业 Know-How / 标杆客户" | 行业方案+AI 能力嫁接，行业 domain 深度 > 技术深度 | 业界 25% |

### B.2 自动判定算法（调研 Step 4 集成）

```
1. 扫描 JD 全文 → 提取关键词集合 K
2. 计算 K 与各类型关键词集的命中率
3. 命中率 ≥40% 的类型 = 主类型
4. 命中率 20-40% = 副类型
5. 都 <20% → 模糊型，必须 HR 电话澄清"日常工作大致是什么"
```

**示例**：简圣 AI 产品经理 JD
- "Agent 编排 / Skills / RAG / Prompt Engineering / Tool Calling" → 技术 AI PM 命中 5/6 = 83%
- 真实工作中 "负责协同各岗位 / 直播间 / B 端方案 / 分公司协同"（这些 JD 没写但实际是）→ 业务总线 PM 真实命中 80%
- **结论**：JD 描述与实际工作错位是初创公司常见现象 → 类型预判**必须叠加 HR 电话/面试开场二次校准**

### B.3 每类型的自我介绍主线 + 弹药选择

#### 🤖 技术 AI PM 主线

> "我专注 AI Agent 编排 + 模型评测体系。最近做了 [项目] —— [Agent 类型]，4 模型 × 50 评测决策模型选型，落地 [数据]。我看你们的 [产品] 是 [技术 stack]，和我自搭的 [类似工具] 底层同构。"

- **核心弹药**：4 模型 × 50 评测 / Agent 编排架构 / RAG 4 道门 / 抗 Prompt 注入 5 层 / 模型选型 3 层决策
- **压题方向**：100 题中技术（C+E 板块）占 60%

#### 📊 业务总线 PM 主线（🔴 错配最常见）

> "我做 AI 产品方向 1-N 落地，过去 X 年负责 [业务 / 产品] 的整体增长。在 [项目] 我同时管运营、市场、开发协同——比如 [一个跨职能协同的具体 case]。带的不是 PRD 是业务。"

- **核心弹药**：用户增长 AARRR 漏斗 / 业务总线协同案例 / 跨部门推动困难案例 / RICE 排优先级 / 一句话连接业务卡点和自己经验
- **压题方向**：100 题中业务（D 板块）占 50%，技术压题降到 20%

#### 📚 内容运营 PM 主线

> "我做 AI 智能体运营方向，懂 Prompt 工程也懂内容运营。在 [项目] 做了 [人设 / 矩阵号 / 数字人] —— [数据]。Prompt 四件套（角色/约束/样本/格式）+ 用户分四层是我每天用的工作语言。"

- **核心弹药**：Prompt 四件套 / 用户分四层 / 矩阵号运营经验 / 私域转化漏斗 / 内容资产 × AI 二次利用
- **压题方向**：100 题中内容运营（D + G 板块）占 55%

#### 🏭 行业方案 PM 主线

> "我做 AI + [行业] 方向，对 [行业 domain] 有 X 年积累。在 [项目] 和 [客户 type] 联合共研做了 [方案]，POC 跑通后规模化到 [数据]。"

- **核心弹药**：行业 Know-How 案例 / POC → 规模化路径 / 客户联合共研经验 / 行业准入资质了解 / 数据壁垒
- **压题方向**：100 题中行业（D 板块）占 45%，行业资质/合规占 15%

### B.4 PM 类型 × 面试官类型 = 16 宫格策略

| | 技术深究 | 业务总操盘 | HR 流程 | CEO 战略 |
|---|---|---|---|---|
| 技术 AI PM | 主战场 ✅ | **谨慎！** 不要堆技术 | 软性 + 文化 | 行业判断 + 远期 |
| 业务总线 PM | **谨慎！** 不要装技术深度 | 主战场 ✅ | 软性 + 业绩故事 | 业务洞察 + 远期 |
| 内容运营 PM | 不要硬聊架构 | 业务+内容协同 | 主战场 ✅ | 内容 IP × AI 战略 |
| 行业方案 PM | 行业技术接口 | 客户协同案例 | 软性 + domain | 主战场 ✅（行业判断） |

**用法**：作战地图 Ch6 岗位解剖必须明确**预测的 PM 类型 × 面试官类型组合**，并选定对应主策略。
