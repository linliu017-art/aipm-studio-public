# Agent Note: 独立的项目文档历史

Status: implemented

English | [中文](2026-11-03-project-documents.md)

## Problem

阶段目录、技能来源和工坊版本文件夹叠成了用户看到的文档层级。普通 PRD 与工坊方案采用不同保存规则，工坊流程的 V 编号也不能表示每份文档的版本。直接覆盖普通文件会丢失此前内容。

## Decision

每份文档有自己的标识、标题、类型和历史版本。普通对话与工坊共用项目内的保存入口。在共享写入锁内，先准备文档目录中的不可变文件，再通过原子替换内部文档索引发布。普通对话与工坊更新均要求准确的文档标识和读取时的文档版本，不按同名标题选择文档。同一次提交关联内部工坊方案快照，流程计数与文档版本保持独立。

旧阶段产出保持原样。整理时为原始字节建立快照并记录原路径，已知工坊版本仅按完全一致的稳定文档路径归组，不自动合并普通 PRD 和工坊 PRD。在新的统一提交替代前，已有工坊方案元数据仍可读取。索引损坏、版本过期、已登记文件缺失或路径重定向会阻止写入，避免丢弃历史。

项目页按类型显示文档，直接打开当前版本。历史记录提供旧文件、生成来源及属于当前项目的来源对话。实际存储文件夹与内部 JSON 保持隐藏，数量按文档计数，不按版本文件计数。阶段状态单独记录，不显示编号，也不自动创建阶段文件夹。

## Consequences

已有文件链接仍然有效。导入历史反映整理时的内容，此前已被覆盖的内容无法恢复。进程中断留下的未提交文件没有索引记录，不会发布。原子替换不承诺 fsync 崩溃耐久性。整理后再手改保留的原文件，不会改变已提交的当前文档；后续编辑使用统一保存操作。

## Verification

文件系统测试覆盖独立版本、旧文件精确归组、原文保留、同名文档分离、过期并发保存、部分批次拒绝、索引损坏和路径重定向。真实 Loader 测试调用普通保存与工坊保存，并验证卸载后工具移除。组件和读取器测试覆盖文档计数、当前和历史预览、来源对话授权及内部路径隐藏。记录会话重放固定模型可见的工具和预设变化。浏览器验证覆盖实际文档、右侧预览、历史和窄窗口及浅深主题。

## Alternatives considered

只把旧目录树压平，仍会保留两套不一致的保存规则。按标题合并可能混合无关文档。移动或覆盖原文件会破坏链接与人工修改。项目统一版本号会让独立变更的文档看起来属于同一次更新。
