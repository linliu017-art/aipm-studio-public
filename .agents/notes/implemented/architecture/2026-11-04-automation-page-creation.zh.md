# Agent Note：在任务页面创建定时任务

Status: implemented

[English](2026-11-04-automation-page-creation.md) | 中文

## 问题

任务页面的“新建”会跳转到对话，用户无法在管理页面直接创建定时任务。调度投递仍依赖会话，会话和任务分别保存。

## 决策

页面表单收集任务名称、指令、可选工作区，以及一次、每天或每周的时间。提交前分配稳定会话标识和请求 UUID，再创建或复用会话并调用关联会话的 Schedule 远程接口。Schedule 串行化写入，并在相同标识重试时复用已保存记录，避免未确认响应导致自动重复创建。提交前取消不产生写入；失败后保留提交内容供用户主动重试。原有模型工具和任务编辑继续使用同一服务。

## 提前提醒

可选的提前时间按任务标识保存在当前浏览器中。全局页面提示监听权威任务目录，按执行时点保存未确认的提醒；提醒在刷新后保留至用户关闭或任务时间到达。设置和提醒只属于当前浏览器，不提供系统通知。轻量提醒可打开对应任务或在剩余时间超过五分钟时延后五分钟提醒，不会改变任务执行时间。

## 刷新和提示音

当前主面板与选中的任务保存在当前标签页的 session storage，主面板注册后恢复。用户交互后新提醒播放短提示音；刷新恢复的提醒不重播，声音不可用时不影响提示。

## 考虑过的替代方案

**从「新建」跳转到对话。** 原有入口复用了对话流程，但用户必须离开任务列表才能输入任务内容和时间。在任务页面放置表单后，创建和管理可以在同一处完成。

## 后果

用户可以直接在任务列表创建定时任务。会话创建和任务存储分别写入，客户端需要在重试时保留会话和请求标识。提前提醒仅保存在当前浏览器，换设备时需要单独配置。

## 验证

定向测试覆盖宿主幂等创建及客户端表单行为。隔离 Web 服务验证了创建任务并在列表中显示。完整 GUI 套件目前存在无关失败；浏览器回放的原生组件无法使用当前 macOS SDK 构建。
